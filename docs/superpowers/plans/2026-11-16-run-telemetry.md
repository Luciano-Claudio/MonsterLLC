# Telemetria de Run (RunTelemetryRecorder) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a togglable `RunTelemetryRecorder` that logs a complete, structured JSON record of a play session (kills with hit counts, gold, sales, perk purchases/undos, and a 1Hz time-series of population/position/idle-time) to disk, so balance/fun discussions on the Barbarian can be grounded in real play data instead of memory.

**Architecture:** A single new `MonoBehaviour` (`RunTelemetryRecorder`) added at runtime to the existing "Systems" GameObject (same pattern as `DayStatsTracker`/`KillGoldReward` init calls in `SystemsBootstrap`). It subscribes to the existing `GameEvents` bus for day/shop/kill/damage boundaries, runs a manual per-second timer (not a Coroutine — `GameplayGate` never pauses `Time.timeScale`, confirmed project-wide pattern) for the time-series sampler, and serializes with `JsonUtility` (same as `SaveManager`) to `Application.persistentDataPath/Telemetry/run_<timestamp>.json`, overwriting the whole file at each day/shop boundary. Small, surgical additions to `EnemyController`, `PerkState`, `DayStatsTracker`, `WorldPopulationManager`, `WorldBossSpawnManager`, and `SystemsBootstrap` feed it; none of them change gameplay behavior.

**Tech Stack:** Unity 6 / C#, `JsonUtility` + `System.IO` (project convention, see `SaveManager.cs`), existing `GameEvents` static bus, manual `[ContextMenu]` debug scripts for verification (project has no NUnit/Play Mode test runner — see `Assets/Scripts/Tests/SaveTest.cs`).

**Spec:** `docs/superpowers/specs/2026-11-16-run-telemetry-design.md`

## Global Constraints

- JSON only — no Markdown/text report generated by the script itself.
- Sampling frequency: 1 sample per real second of active gameplay.
- Every sample includes the hero's world position (x, y).
- `GameEvents.cs` lives in the `Core` asmdef and must never reference types outside `Core` — any new event payload is primitives/`Vector3` only (matches existing `OnEnemyKilled(int, bool)`).
- The recorder must cost exactly zero (no subscriptions, no timer, no file) when its enabled checkbox is off.
- Never throw out of an I/O failure into the rest of the game — `try/catch`, `Debug.LogWarning` only.
- Regrava (overwrite) o JSON inteiro a cada fronteira (fim de dia, fim de visita à loja, retorno ao Menu Principal com tentativa aberta) — nunca só no fim da sessão.
- `directHitsTaken` (`isDirectPlayerHit == true`) and `dotTicksTaken` (`isDirectPlayerHit == false`) are always recorded as two separate counters, never summed.

## Review Focus

- Telemetry checkbox off: zero subscriptions, zero timer ticks, zero file — a disabled recorder must not even create the `Telemetry` folder.
- First-ever write on a fresh machine: `Application.persistentDataPath/Telemetry/` does not exist yet — a raw `File.WriteAllText` would throw.
- Same day number retried after death (the project's own known day-retry pattern): `attemptIndex` must increment per `dayNumber`, not globally, and the file must still be valid after several retries of the same day.
- A monster killed purely by damage-over-time (e.g. Ground Crack) with zero direct hits: `directHitsTaken == 0`, `dotTicksTaken > 0`, no divide-by-zero or "monster died with 0 hits" miscount.
- "Voltar ao Menu Principal" with nothing open (fresh boot, or right after a shop visit before the next day started): the scene-loaded handler must no-op safely, never `NullReferenceException`.
